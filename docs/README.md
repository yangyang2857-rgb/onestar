# docs 目录索引

本目录存放拾光 OneStar 的跨平台开发与发布规范。**规范类文档只在发版前被读取，所以必须保证"打开就知道该看哪一节"**。

## 文档关系

```
docs/
├── README.md                        ← 本文件：目录索引
├── 全生态开发与发布总纲.md            ← 唯一入口：跨平台统一口径、时间表、闸门
├── 发版规范.md                       ← 版本号、CHANGELOG、提交信息、发布度量
├── 签名与覆盖升级.md                  ← 证书固定、CI Secret 注入、验签与排错
├── 拾光OneStar_版本时间轴.md          ← 历代版本与语义化版本号对照
├── screenshots/                     ← README 与商店素材用截图
└── ecosystems/                      ← 原子文档：单平台的完整原文（含命令与逐项清单）
    ├── 安卓全生态开发与发布要点.md
    ├── Web全生态开发与发布要点.md
    ├── 鸿蒙全生态开发与发布要点.md
    ├── 苹果全生态开发与发布要点.md
    ├── Windows全生态开发与发布要点.md
    └── Linux全生态开发与发布要点.md
```

## 阅读顺序

1. **先读总纲**。它解决的是"六个平台放在一起时哪些是同一件事"，包含：全局时间表（已生效/待生效）、身份与签名锚点、跨平台共性矩阵（布局/体积/隐私）、统一发布闸门 12 道、风险矩阵、源文档核查修正记录。
2. **需要具体命令或逐项清单时，再翻对应生态的原子文档**。总纲不复制命令与代码片段，避免两处维护、两处漂移。

## 维护约定

- **总纲是派生文档**：平台政策变化时，先改 `ecosystems/` 原文，再同步总纲的对应表格。不要只改总纲。
- **总纲改动必须回写 README**：总纲的时间表、SDK 门槛、ESU 等时效性条目改完后，同步根 `README.md` 的 §12.1 摘要与顶部 targetSdk badge，否则会留下"总纲对、README 错"的第二份事实。
- **无出处不写精确日期**：凡是精确到日的平台节点必须有官方原文；没有就写"某月起"或标 ⚠️ 推断。
- **每季度复跑一次时效检查**（§8 末）：Android target API、Apple SDK 门槛、Windows App SDK 版本、HarmonyOS 上架规则。四项都在变。
- **日期一律写绝对日期**（`2026-08-31`），不写"明年""下个季度"，避免文档老化后产生误判。
- **"已生效"与"待生效"必须分开标注**。已生效项的含义是"现在不满足就发不出去"，不是"将来注意"。
